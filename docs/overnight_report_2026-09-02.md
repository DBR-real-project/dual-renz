## 1. FE↔BE 연동 점검 — 정상, 단 치명적 버그 1건 발견·수정

### 정적 대조
- `web/app.js`가 호출하는 모든 엔드포인트(`/api/analyze`, `/api/jobs/{id}`,
  `/api/results/{id}`, `/ws/jobs/{id}`, `/api/history[/{id}]`, `/api/sessions*`,
  `/api/health`)가 `src/api/main.py`의 실제 라우트와 1:1로 일치.
- `app.js`의 모든 `$('id')` 참조(DOM id)가 `index.html`에 전부 존재 — 누락 0건.
- `index.html`은 `/static/...` 경로로 정적 리소스를 참조 — 서버의
  `app.mount("/static", ...)` 마운트와 일치.

### 실동작 검증 (headless Chromium, 실제 서버)
- 온보딩 → 홈 → 보호이력 → 업로드 → **실제 파일 분석(both_real.mp4)** → 결과
  화면까지 전체 플로우를 클릭으로 실행, **콘솔 에러 0건**.
- 결과 화면 렌더(도넛/게이지/차트/타임라인/RAG 근거)까지 정상 표시 확인.
- 히스토리 CRUD(`GET/DELETE /api/history[/{id}]`) 전부 정상.

### 🔴 발견한 치명적 버그 → 수정 완료
**증상**: 실시간 화상통화 검증 화면에서 청크가 5초마다 전송되는데, **두 번째
청크부터 전부 조용히 실패**한다(`app.js`가 실패를 흡수해 사용자에게 에러가
안 보임 — 위험도가 첫 5초 값에서 그냥 멈춘 채 변하지 않는다).

**원인**: Chromium의 `MediaRecorder.start(timeslice)`는 EBML/WebM 헤더를
**첫 청크에만** 싣는다. 두 번째 청크부터는 헤더 없는 Cluster 데이터만 와서
ffmpeg이 독립된 컨테이너로 디코딩하지 못한다(`EBML header parsing failed`).
`extension/offscreen.js`도 동일한 패턴을 쓰므로 크롬 확장도 같이 영향받는다.

headless 브라우저로 실제 청크를 캡처해 격리 재현 → chunk0만 EBML 헤더 보유,
chunk1~3은 전부 디코딩 실패를 직접 확인했다(`fake device` 특유의 문제가 아니라
Chromium의 실제 동작임을 별도로 검증).

**수정**: `src/orchestration/streaming.py`. 세션이 첫 webm 청크에서 초기화
세그먼트(EBML~Cluster 이전)를 캐싱해두고, 헤더 없는 후속 청크 앞에 붙여서
디코딩 가능한 스트림으로 복원한다. **서버 쪽 수정이라 웹 대시보드와 크롬 확장
둘 다 동시에 고쳐진다** (클라이언트 코드는 안 건드림).

**검증**:
- 격리된 실제 브라우저 청크로 재현 → 수정 후 400 → 200으로 전환.
- `audio_sec`가 청크마다 정상 누적됨을 확인 (2.0 → 4.0 → 5.9초).
- 기존 팀 E2E 테스트 `scripts/test_streaming.py`(wav 경로라 이 버그를 안 타던
  테스트) 재실행 — 회귀 없음, 78초 통화 33초에 처리 완료.
- headless 브라우저로 실시간 화면 재검증 — 400 에러 사라짐.

**출처 정직성**: 웹 검색으로는 언론이 통화 대사를 그대로 인용한 사례가 드물었다
(대부분 경위만 서술). 그래서 `_meta`에 정책을 명시했다 — 실제 인용문 3건은
`source`에 "(기사 인용문)"으로, 사실관계만 있고 팀이 대사를 재구성한 5건은
"(기사 사실관계 기반 — 팀 재구성)" 또는 "실제 대사 아님"으로 **명확히 구분**해
대시보드에 "실제 사례"로 오인 표시되지 않게 했다.

**검증**: ChromaDB 재색인(103 문서) 후 신규 사례 타깃 질의 6건 모두 정확히
매칭(유사도 0.66~0.81, 채택 임계값 0.55 상회). 기존 정상 대조군(case-017,
일상 잡담) 오탐 방지 로직도 회귀 없음 확인(sim=0.986 유지).

## 4. 크롬 확장 — 정상 (사소한 타이밍 이슈 1건, 코드 버그 아님)

`node scripts/test_extension.js` — manifest, 3계층 메시지 흐름, 세션
생성→청크→결과, 밀림 방지, 오버레이 렌더링, 백엔드 다운 시 오류 전파까지
전부 정상.

한 항목만 FAIL: "캡처 종료 후 새 세션 생성 가능" 체크가 1.2초 고정 대기 안에
통과 못 함. **원인 추적 결과 실제 버그 아님** — DELETE 요청은 실제로 정상
전송·처리되지만, 마지막 청크가 아직 STT 추론 중이면(모델 동시접근 방지용
락 때문에) 그 처리가 끝날 때까지 세션 종료가 몇 초 지연될 수 있다. 로그로
DELETE가 결국 200으로 성공하는 것을 확인했다. 테스트 하네스의 1.2초 대기가
너무 짧을 뿐이고, 실사용에서 종료 직후 1~2초 내 즉시 재시작하는 극단적
케이스가 아니면 영향 없다. (참고로 이 테스트는 wav 형태 청크만 써서 위 1번
webm 헤더 버그와는 무관한 경로.)

## 5. 최종 에러 로그 점검 — 완료

- 서버 로그에 traceback/error/exception 없음 (API 키 관련 안내 메시지 제외).
- headless 브라우저 콘솔 에러 0건 (실시간 화면의 세션 종료 시 경쟁 상태로
  인한 404 1건은 `app.js`가 이미 조용히 무시하도록 설계돼 있어 문제 없음).
- 테스트 중 생성된 히스토리 항목/세션은 전부 정리, 서버 재시작으로 클린 상태
  확인. 현재 서버는 `scripts/run_server.py` 그대로 백그라운드에서 계속 실행 중.

## 아직 안 된 것 / 팀이 확인해야 할 것

1. **`web/app.js`, `web/index.html`, `web/style.css`, `docs/*.json`이 언커밋
   상태**로 남아 있다. 내가 작성한 게 아니라 커밋하지 않았지만, 위 1번에서
   이 상태 그대로 실제 서버와 완전히 정상 동작함을 검증했다. 본선 전에
   팀이 검토 후 커밋할 것.
2. **실제 브라우저(Chrome)에서 "화면·탭 공유" 권한 팝업, 실제 탭 오디오
   캡처는 검증 못 함** — headless는 `--use-fake-ui-for-media-stream` 등
   플래그로 우회했다. 이건 사람이 실제 브라우저로 한 번은 눌러봐야 한다.
   (크롬 확장의 `manifest` 권한 승인도 마찬가지.)
3. **LLM API 키(`ANTHROPIC_API_KEY`/`GEMINI_API_KEY`)가 이 환경엔 없다** —
   지금은 오프라인 키워드+임베딩 분류기로 폴백 중(자체 검증 정확도 90.5%).
   심사장에서 LLM 붙여서 더 정확하게 보여주고 싶으면 키를 넣을 것.
4. RAG 신규 사례 중 5건은 "사실관계 기반 재구성" — 실제 통화 대사를 그대로
   인용한 게 아니다(위 2번 표 참고). 발표 중 "실제 판례에서 그대로 가져온
   대사"라고 소개하면 안 되고, "보도된 수법을 바탕으로 구성"이라고 해야 정확하다.
5. 이번에 고친 스트리밍 버그는 심사장 데모에서 실시간 화면을 5초 이상
   켜두면 100% 재현됐을 문제였다. 수정 후 재검증까지 마쳤지만, 가능하면
   아침에 실제 브라우저로 한 번 더 화면 공유 데모를 눈으로 확인해 보는 걸
   권한다.
