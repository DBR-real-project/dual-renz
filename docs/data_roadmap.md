# 데이터 확보 로드맵

작성: 2026-08-18 (이인영 멘토님 피드백 반영) | 갱신 시 날짜를 남길 것

우리 프로젝트의 **성능 한계는 대부분 데이터에서 온다.** 미디어 두 엔진(영상·음성)이
학습 도메인 밖에서 무너지는 게 확인됐고(`validation_report.md` 0-3, 0-7),
공개 모델을 갈아 끼워도 해결되지 않았다(0-3-1). 남은 길은 **한국 통화 도메인
데이터를 확보해 미세조정**하는 것이다.

이 문서는 "그 데이터를 어디서 어떻게 구하는가"를 정리한다.

> **전부 받지 말고 이 패턴을 먼저 검토할 것.**

### ⚠ KsponSpeech 이용 조건

원본은 **AI Hub(한국지능정보사회진흥원)** 「한국어 음성」 데이터셋이고 이용 약관이 있다.
지금은 HuggingFace 공개 미러에서 **검증 목적 30건만** 받아 쓰고 있으며:

- `data/`(gitignore 대상)에만 두고 **저장소에 커밋하지 않는다**
- **재배포하지 않는다.** 문서에는 측정 결과(수치)만 인용하고 출처를 밝힌다
- **학습이나 사업화에 쓰려면 AI Hub에서 정식 이용 신청**이 필요하다

## 2. 신청하면 쓸 수 있는 것 (다음 단계)

### 2-1. AI Hub — 최우선

**https://aihub.or.kr** · 회원가입 후 데이터별 이용 신청 (승인까지 수일)

| 데이터셋 | 우리에게 왜 필요한가 |
|---|---|
| 한국어 음성(KsponSpeech) | 지금 미러로 30건만 쓰는 것을 **정식으로 전량** |
| 고객 응대(콜센터) 음성 | **전화망을 통과한 실제 통화** — 지금 가장 부족한 것 |
| 감성 대화 / 자유 대화 음성 | 화법 분류기의 도메인 밖 검증셋 확대 |
| 딥페이크 변조 영상 | 한국인 얼굴 기반 영상. FF++는 서양인 위주다 |

**콜센터 음성이 핵심이다.** 우리가 못 재고 있는 건 "전화망을 통과한 정상 통화"인데
이게 정확히 그 데이터다.

### 2-2. 공공데이터포털

**https://www.data.go.kr** · API 키 발급 후 사용 (즉시 발급)

- 보이스피싱 피해 통계, 사기 수법 유형 — **RAG 사례 데이터 확충**에 직접 쓸 수 있다
- 지금 RAG 사례가 26건이고(국내 보도 기반 8건을 더했다) 여전히 대부분 팀이 정리한
  것이라, 공공 통계로 보강하면
  "실제 사례"라는 근거가 생긴다

### 2-3. KISA / 경찰청 사이버수사

- **KISA(한국인터넷진흥원)** — 피싱 관련 자료, 신고 통계
- **경찰청 사이버수사국 / 사이버범죄 신고시스템(ECRM)** — 수법 유형 자료
- 기관 협조가 필요한 영역이라 **팀 차원의 문의**가 선행돼야 한다

### 2-4. 음성 데이터 추가 경로 (멘토님 제안)

| 경로 | 성격 | 비고 |
|---|---|---|
| 우리소리박물관 | 국악·민요 음원 | 통화체는 아니지만 **한국어 진짜 사람 음성** 다양성 확보 |
| 라디오 / 팟캐스트 | 대화체, 전화 연결 코너 존재 | **라디오 전화 연결**은 실제 전화망 음성이라 가치가 크다. 저작권 확인 필수 |

> 라디오 전화 연결 코너는 우리가 찾는 "전화망 통과 정상 대화"에 가장 가깝다.
> 다만 방송 저작권이 있으므로 **연구 목적 이용 가능 여부를 먼저 확인**할 것.

## 3. 가명화 데이터라는 선택지

멘토님 조언: **익명화가 아니라 「가명화」 데이터**를 활용하는 방법이 있다.

- **익명화** — 개인 식별 정보를 완전히 제거. 복원 불가. 데이터 가치가 많이 손실된다.
- **가명화** — 식별자를 가명으로 치환. 추가 정보 없이는 식별 불가.
  개인정보보호법상 **통계·연구 목적으로 정보주체 동의 없이 처리 가능**한 여지가 있다.

의료 분야(예: 피부 관련 의료 데이터)에서 이 방식이 자리 잡았다.
**통화 데이터에 같은 틀을 적용할 수 있는지** 조사가 필요하다.

우리 경우 통화 녹취에서:
- 이름·계좌번호·주민번호 등을 가명으로 치환
- 음성 자체는 화자 식별이 가능하므로 **음성 가명화(화자 변환)** 가 별도로 필요
- 이 부분은 법률 검토가 선행돼야 한다

## 4. 사업 연계 (중장기)

멘토님 조언: 데이터 한계가 명확하다면 **정부기관 사업과 연계해 데이터를 얻는 것**이
현실적인 고도화 경로다. AI 규제 논의가 진행 중이라 **국가적으로도 중요한 사안**이다.

발표에서 이렇게 연결할 수 있다:

> 지금 성능의 한계는 **모델이 아니라 데이터**입니다. 공개 데이터로는 여기까지가
> 한계라는 걸 실측으로 확인했습니다(공개 모델 4종 비교 포함).
> **실제 통화 도메인 데이터를 확보하면 개선됩니다.** 그건 개인정보 문제 때문에
> 기관 협력이 필요한 영역이고, 그래서 **B2B(금융기관·통신사)·공공 협업**이
> 자연스러운 다음 단계입니다.

- **B2B** — 은행·카드사 고객센터, 통신사 (이미 통화 데이터를 보유)
- **B2C** — 앱 사용자의 동의 기반 데이터 수집 (옵트인)
- **공공** — 금감원·경찰청과의 협업. 「그놈 목소리」처럼 공익 목적 데이터가 이미 존재

## 5. 우선순위

| 순위 | 할 일 | 기대 효과 | 난이도 |
|---|---|---|---|
| 1 | **AI Hub 콜센터 음성 신청** | 전화망 통과 정상 통화 확보 → 음성 엔진 헛경보 문제 직격 | 낮음(신청만) |
| 2 | **공공데이터포털 API** | RAG 사례 26건 → 대폭 확충 | 낮음 |
| 3 | 주변 사람 검증 | 검증 주체가 없는 상황의 차선책 | 낮음 |
| 4 | 라디오 전화 연결 음성 | 실제 전화망 음성 | 중간(저작권) |
| 5 | 가명화 데이터 법률 검토 | 실제 통화 데이터 활용 근거 | 높음 |
| 6 | 기관 협업 / 사업 연계 | 근본 해결 | 높음(장기) |

**1번이 가장 값어치가 높다.** 신청만 하면 되고, 우리가 못 재고 있는 바로 그 데이터다.
